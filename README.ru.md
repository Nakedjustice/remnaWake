# 🌙 remnaWake

[English](README.md) · **Русский**

Лёгкий Go-сервис, который раз в сутки опрашивает панель
[Remnawave](https://remna.st) и напоминает пользователям в Telegram об истечении
подписки (за 7 / 3 / 1 день). Администратор может прямо из чата подтвердить
оплату — и бот продлит подписку на выбранное число месяцев.

## ✨ Возможности

- ⏰ **Напоминания** за 7 / 3 / 1 день до окончания плюс **возвращающие**
  сообщения через 1 и 3 дня *после* окончания (`WINBACK_DAYS` / `WINBACK_ENABLED`).
- 💳 **Подтверждение оплаты** — пользователь нажимает **«Я оплатил»**, админ
  подтверждает, бот продлевает подписку через `PATCH /api/users`. Опционально —
  автоматическая онлайн-оплата через **Platega** (СБП / карты) и/или
  **Telegram Stars** (⭐).
- 👤 **Личный кабинет** (`/me`) — привязанные профили, статус, срок, ссылка на
  подписку, сводка подарков/приглашений и быстрые действия.
- 🔗 **Самостоятельная привязка** (`/register`) — вставьте ссылку на подписку или
  имя профиля, и бот привяжет ваш Telegram ID без участия админа.
- 🎁 **Подарки** (`/gift`, `/mygifts`) — купить подписку как передаваемый
  одноразовый код / deep-link `t.me`; получатель активирует сам.
- ➕ **Приглашения** (`/invite`) — подписчики запрашивают новый аккаунт в панели;
  админ одобряет, и ссылка на подписку отправляется обратно.
- 📊 **Статистика** (`/stats`) — пользователи панели, оплаты и выручка за 30 дней,
  подарки, приглашения.
- 🖥 **Мини-приложение Telegram** — веб-версия кабинета (задайте `WEBAPP_URL`).
- 🗃 **Надёжность** — каждое уведомление дедуплицируется в SQLite (без повторов
  при перезапуске), неудачные отправки повторяются, Telegram `429` ретраится.
- 🌍 **Русский или английский** интерфейс (`BOT_LANG`, по умолчанию русский).
- 🐳 Distroless multi-stage Docker-образ, `restart: unless-stopped`,
  структурированные JSON-логи в stdout.

## 🔔 Уведомления

```
⏰ ivan, ваша подписка истекает 17.06.2026 — через 7 дней.
Для продления оплатите подписку.
```

В каждом сообщении указывается **имя профиля** Remnawave и **точная дата**
окончания (`ДД.ММ.ГГГГ`); слово «день/дня/дней» согласуется с числом.
Уведомляются только пользователи `ACTIVE` с `telegramId`; аккаунты `DISABLED` /
`LIMITED` не беспокоятся.

Если задан `TELEGRAM_ADMIN_ID` (используйте **Telegram user ID** администратора,
а не chat ID группы/канала), к сообщению добавляется inline-кнопка
**«Я оплатил»**. Каждое напоминание записывается в SQLite до отправки, поэтому
перезапуск не приведёт к повторному сообщению; неудачные отправки повторяются
при следующем ежедневном запуске.

**Возврат после окончания (win-back)** — если подписка истекла (статус `EXPIRED`
или `ACTIVE` с датой в прошлом), бот отправляет возвращающее сообщение с той же
кнопкой через 1 и 3 дня; подтверждение продлевает от `max(сейчас, старый срок)`.

```
⛔️ ivan, ваша подписка истекла 10.06.2026.
Чтобы продолжить пользоваться сервисом, продлите подписку.
```

## 💳 Подтверждение оплаты (опционально)

Активно только при заданном `TELEGRAM_ADMIN_ID`:

1. Пользователь нажимает **«Я оплатил»**. Если заданы **реквизиты**
   (`/setrequisites`), бот сначала отправляет их (например, карта / СБП).
2. Если заданы тарифы, бот показывает варианты месяцев/цен (`1 мес. — 150₽`, …);
   иначе — запасной вариант на 1 месяц.
3. **Администратор** получает данные клиента и выбранные месяцы/цену с кнопкой
   **«Подтвердить оплату»**.
4. После подтверждения бот вызывает `PATCH /api/users` и продлевает на выбранные
   месяцы от `max(сейчас, текущий срок)`, затем сообщает новый срок.

Цены **информационные** — в режиме P2P бот не проводит платежи; пользователь
платит вам внешним способом, а вы подтверждаете вручную.

### ⚡ Автоматические провайдеры: Platega и Telegram Stars (опционально)

Кроме P2P можно включить шлюз **Platega** (СБП / карты) и/или **Telegram Stars**
(встроенная валюта Telegram, XTR) для *автоматической* онлайн-оплаты. Включайте
любую комбинацию на лету — пункт **💳 Способы оплаты** в меню `/admin` или выбор
в админ-панели Mini App. **Можно включить несколько сразу**; если включено
больше одного, пользователь выбирает способ при оплате.

- 🏦 **Platega** — задайте `PLATEGA_MERCHANT_ID` + `PLATEGA_SECRET` (см.
  `.env.example`). После выбора тарифа пользователь получает ссылку **«Оплатить»**
  и кнопку **«🔄 Проверить оплату»**; Platega вызывает вебхук
  `POST /platega/callback` (тот же HTTP-сервер, что и Mini App — укажите этот URL
  как адрес уведомлений в кабинете Platega), бот заново проверяет статус и
  продлевает подписку.
- ⭐ **Telegram Stars** — задайте `TELEGRAM_STARS_ENABLED=true` и
  `TELEGRAM_STARS_RATE` (единиц цены за одну звезду; списывается
  `ceil(цена / rate)` звёзд), затем включите в админ-выборе **Способы оплаты**.
  Не нужны ни дополнительные ключи, ни вебхук — используется токен самого бота, и
  бот отправляет нативный счёт Telegram (валюта `XTR`) прямо в чат (в Mini App
  открывается встроенная форма оплаты). Подтверждение приходит через `getUpdates`
  (`pre_checkout_query` → `successful_payment`).

Все подтверждения **идемпотентны** — повторные вебхуки, нажатия или события
оплаты не продлевают подписку дважды.

### 📸 Чек об оплате (опционально)

Переключатель **«📸 Чек об оплате»** в `/admin` или Mini App требует
подтверждение оплаты: после выбора тарифа пользователь должен отправить **фото,
скриншот или PDF** до создания заявки; администратор получает её с вложением и
обычными кнопками подтверждения/отказа. Шаг истекает через 10 минут (`/cancel`
отменяет). Продление, начатое из Mini App, продолжается в чате с ботом.

## ⌨️ Команды

**Пользователь** (доступны всем, кто пишет боту):

| Команда     | Что делает                                                    |
| ----------- | ------------------------------------------------------------- |
| `/start`    | Приветственное сообщение + инструкция по привязке             |
| `/me`       | Личный кабинет: статус, ссылка, подарки/приглашения, действия |
| `/menu` · `/help` | Открыть меню с inline-кнопками                          |
| `/tariff`   | Показать текущие тарифы/цены                                  |
| `/gift`     | Купить подарочную подписку и получить код (для подписчиков)   |
| `/mygifts`  | Список подарочных кодов, их статус и повторная отправка ссылки |
| `/invite`   | Пригласить нового пользователя в панель (для подписчиков)     |
| `/register` | Привязать Telegram к существующему профилю Remnawave          |
| `/cancel`   | Отменить текущий шаг `/gift` / `/invite` / `/register`        |

**Администратор** (только `TELEGRAM_ADMIN_ID`; для остальных молча игнорируются):

| Команда                       | Что делает                  |
| ----------------------------- | --------------------------- |
| `/tariffs`                    | Список тарифов              |
| `/settariff <месяцев> <цена>` | Добавить или обновить тариф |
| `/deltariff <месяцев>`        | Удалить тариф               |
| `/setrequisites`              | Задать реквизиты, показываемые после «Я оплатил» (в два шага) |
| `/requisites`                 | Показать сохранённые реквизиты |
| `/stats`                      | 📊 Пользователи панели, оплаты и выручка за 30 дней, заявки, подарочные коды, приглашения |

В меню **`/admin`** также есть 📊 статистика, браузер 🎁 подарочных кодов (по
покупателю → использованы/не использованы → сами коды, с отзывом в один тап) и
выбор 🛡 **сквада по умолчанию** для новых пользователей из `/gift` и `/invite`
(откат на стоковый `Default-Squad`; если сквад не найден, создание завершается
видимой ошибкой). Те же элементы есть в админ-панели Mini App.

Тарифы и состояние оплат хранятся в SQLite (`DB_PATH`, по умолчанию
`/data/bot.db`, в Docker-томе `botdata`), поэтому переживают перезапуск.

**Защита** — подтверждать оплату, одобрять приглашения/подарки, отзывать коды и
управлять тарифами может только админ; подтверждение оплаты идемпотентно; новый
срок = `max(сейчас, текущий срок) + выбранные месяцы`, поэтому позднее
подтверждение не оставит дату в прошлом.

## 🎁 Подарки (`/gift`)

Получателя знать заранее не нужно — покупатель получает передаваемый код:

1. Отправьте `/gift` (или нажмите **🎁 Подарить подписку**); бот покажет реквизиты
   и кнопки тарифов.
2. Выберите период → админ получит заявку с **«✅ Подтвердить оплату»** /
   **«❌ Отклонить»**.
3. После подтверждения покупатель получает одноразовый код и deep-link
   `https://t.me/<бот>?start=gift_<КОД>`.
4. Получатель открывает ссылку (или отправляет `/start gift_<КОД>`): существующий
   привязанный профиль **продлевается**; иначе бот спрашивает имя пользователя,
   **создаёт** профиль, привязывает Telegram и присылает ссылку на подписку (срок
   идёт с момента активации).
5. Покупатель получает уведомление об активации.

Каждый код строго **одноразовый** (атомарная отметка в базе — без двойного
списания), переживает перезапуск и действует до активации или отзыва. Команда
`/gift` доступна только подписчикам; каждая покупка подтверждается админом.
Проверка в любой момент через `/mygifts` (**📦 Мои подарки**) — у выданных кодов
есть кнопка **🔗** для повторной отправки потерянной ссылки.

## ➕ Приглашения (`/invite`)

Любой подписчик может запросить новый аккаунт Remnawave:

1. Отправьте `/invite`.
2. Введите желаемое **имя пользователя** (3–32 символа, буквы / цифры /
   подчёркивание).
3. Бот покажет стоимость (тариф на 1 месяц) и кнопку **«Отправить заявку»**
   (`/cancel` отменяет).
4. Админ получит **«✅ Одобрить»** / **«❌ Отклонить»**; при одобрении бот создаёт
   пользователя и отправляет ссылку на подписку пригласившему.

## 🔗 Привязка (`/register`)

Уже есть аккаунт Remnawave, но Telegram не привязан? Просто **вставьте ссылку на
подписку** в чат — без команд: бот найдёт профиль по короткому UUID
(`GET /api/users/by-short-uuid/{shortUuid}`) и предложит привязку. Явный
сценарий:

1. Отправьте `/register` (или нажмите **🔗 Привязать аккаунт**).
2. Отправьте **ссылку на подписку** или **имя профиля**.
3. Бот найдёт аккаунт; если не привязан — попросит подтверждение.
4. Нажмите **«Привязать»** — бот вызовет `PATCH /api/users` и сразу привяжет вас.

Уже привязан к вам → подтверждается идемпотентно. Привязан к другому → отказ
(обратитесь к админу). Сессия истекает через 10 минут. При запуске бот
регистрирует меню команд через `setMyCommands`, поэтому появляется синяя кнопка
**Меню** и автодополнение по `/`.

## 🔄 Автообновление (опционально)

При `AUTOUPDATE_ENABLED=true` бот периодически проверяет реестр на новую версию
`AUTOUPDATE_IMAGE` и присылает всем админам сообщение с кнопками
**🔄 Установить сейчас** / **Позже** (интервал `AUTOUPDATE_CHECK_INTERVAL`, по
умолчанию `6h`).

Поскольку бот работает как distroless-контейнер без привилегий, **установка в
один тап** делегируется sidecar-контейнеру
[Watchtower](https://containrrr.dev/watchtower/) в режиме HTTP-API по триггеру.
Раскомментируйте сервис `watchtower` и сеть `autoupdate` в
[`docker-compose.yml`](docker-compose.yml) и задайте `AUTOUPDATE_ENABLED=true`,
`WATCHTOWER_URL=http://watchtower:8080` и общий `WATCHTOWER_TOKEN`. По кнопке
**Установить сейчас** бот вызывает `/v1/update` Watchtower; доступ к
Docker-сокету есть только у Watchtower. Если `WATCHTOWER_URL` пустой — режим
«только уведомления» с командой `docker compose pull && docker compose up -d`.
Всё можно настроить через `install.sh`.

## 🖥 Мини-приложение Telegram

Если задан `WEBAPP_URL`, бот поднимает мини-приложение «Личный кабинет» и
регистрирует его как **кнопку меню** чата (плюс кнопка «🖥 Открыть
мини-приложение» внутри `/me`). В нём видны привязанные профили, статус и срок,
ссылка на подписку с копированием в один тап, реквизиты, сводка подарков и
приглашений, а также выбор тарифа с отправкой заявки на продление админу.
Переключатель языка 🇷🇺/🇬🇧 (вверху справа) по умолчанию берёт язык Telegram
пользователя (с откатом к `BOT_LANG`) и запоминает явный выбор.

**Что нужно** — мини-приложение раздаёт сам бот на `WEBAPP_LISTEN` (по умолчанию
`:8080`). Telegram открывает мини-приложения только по **HTTPS**, поэтому
поставьте впереди реверс-прокси (nginx / Caddy / Traefik) и укажите в
`WEBAPP_URL` публичный HTTPS-адрес. Запросы аутентифицируются проверкой Telegram
`initData` (HMAC-подпись токеном бота) — дополнительные секреты не нужны.

### Шаблоны для реверс-прокси

В обоих шаблонах замените `bot.example.com` на свой домен.

**Caddy** (`/etc/caddy/Caddyfile`) — TLS выпускается автоматически:

```caddyfile
bot.example.com {
    reverse_proxy 127.0.0.1:8080
}
```

**nginx** (`/etc/nginx/sites-available/remnawake-webapp`) — предполагаются
сертификаты certbot (`certbot --nginx -d bot.example.com`):

```nginx
server {
    listen 443 ssl;
    http2 on;
    server_name bot.example.com;

    ssl_certificate     /etc/letsencrypt/live/bot.example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/bot.example.com/privkey.pem;

    location / {
        proxy_pass http://127.0.0.1:8080;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}

server {
    listen 80;
    server_name bot.example.com;
    return 301 https://$host$request_uri;
}
```

```bash
sudo ln -s /etc/nginx/sites-available/remnawake-webapp /etc/nginx/sites-enabled/
sudo nginx -t && sudo systemctl reload nginx
```

### Рядом с remnawave (Caddy в контейнере)

Если у вас уже работает [remnawave](https://remna.st) со своим Caddy **в
контейнере**, не используйте `127.0.0.1:8080` — внутри контейнера Caddy этот
адрес указывает на сам Caddy. Бот должен быть доступен по **имени контейнера**
через общую сеть.

**1. Подключите бота к сети remnawave** (без блока `ports:`):

```yaml
services:
  bot:
    image: ghcr.io/nakedjustice/remnawake:main
    pull_policy: always
    container_name: remnaWake-bot
    restart: unless-stopped
    env_file:
      - ./.env
    environment:
      DB_PATH: /data/bot.db
    volumes:
      - botdata:/data
    networks:
      - remnawave-network

networks:
  remnawave-network:
    name: remnawave-network
    external: true

volumes:
  botdata:
```

**2. Добавьте сайт в существующий `Caddyfile`**:

```caddyfile
https://bot.example.com {
    reverse_proxy remnaWake-bot:8080
}
```

**3. Укажите этот адрес в `WEBAPP_URL`** в `.env`, затем поднимите бота и
перезагрузите Caddy (сначала убедитесь, что DNS указывает на сервер, иначе Caddy
не выпустит сертификат):

```bash
docker compose up -d            # в каталоге remnaWake
docker compose restart caddy    # в каталоге caddy
```

| Переменная               | Обязательна | По умолчанию      | Описание                                                         |
| ------------------------ | ----------- | ----------------- | ---------------------------------------------------------------- |
| `REMNAWAVE_BASE_URL`     | да          | —                 | Базовый URL панели                                               |
| `REMNAWAVE_API_TOKEN`    | да          | —                 | API-токен панели Remnawave                                       |
| `TELEGRAM_BOT_TOKEN`     | да          | —                 | Токен Telegram-бота (от @BotFather)                              |
| `TELEGRAM_PARSE_MODE`    | нет         | `HTML`            | `HTML` / `MarkdownV2` / пусто                                    |

| `RUN_AT`                 | нет         | `09:00`           | Локальное время ежедневного запуска (`HH:MM`)                    |
| `LOG_LEVEL`              | нет         | `info`            | `debug` / `info` / `warn` / `error`                              |
| `HTTP_TIMEOUT`           | нет         | `15s`             | Таймаут HTTP-запросов (Go duration)                              |

| `WEBAPP_URL`             | нет         | —                 | Публичный HTTPS-адрес мини-приложения (пусто = выключено)        |
| `WEBAPP_LISTEN`          | нет         | `:8080`           | Локальный адрес сервера мини-приложения (за реверс-прокси)       |
| `WINBACK_ENABLED`        | нет         | `true`            | Отправлять возвращающие сообщения после окончания подписки      |

## 🚀 Запуск

### Установка на сервер (рекомендуется)

Бот работает из готового образа GHCR, поэтому на сервер попадают только
`docker-compose.yml` и `.env`. Одна команда запускает интерактивный установщик,
который пишет их в **`/opt/remnaWake`** (нужны права root):

```bash
curl -fsSL https://raw.githubusercontent.com/Nakedjustice/remnaWake/main/get.sh | sudo bash
```

Установить в другое место (для доступного на запись пути root не нужен) — через
`TARGET_DIR`:

```bash
curl -fsSL https://raw.githubusercontent.com/Nakedjustice/remnaWake/main/get.sh | TARGET_DIR="$HOME/remnaWake" bash
```

Либо запустите установщик напрямую (ставит в текущий каталог, переопределяется
через `REMNAWAKE_DIR`):

```bash
mkdir -p ~/remnaWake && cd ~/remnaWake
curl -fsSL https://raw.githubusercontent.com/Nakedjustice/remnaWake/main/install.sh | bash
```

Установщик спросит URL панели, токены, ID администратора, таймзону, время запуска
(а также опциональные настройки Mini App и Platega), запишет `.env` (права `600`)
и `docker-compose.yml` и предложит скачать образ и запустить. Нужны `curl` (либо
`wget`) и Docker Engine с плагином Compose — `git` не требуется.

### Локально (разработка)

```bash
cp .env.example .env
# отредактируйте .env
go mod download
go run .
```

### Docker (готовый образ)

```bash
cp .env.example .env
# отредактируйте .env и укажите TELEGRAM_ADMIN_ID для всех дополнительных сценариев
docker compose up -d          # скачивает ghcr.io/nakedjustice/remnawake:latest
docker compose logs -f
```

Обновление позже:

```bash
docker compose pull && docker compose up -d
```

### Docker (сборка из исходников)

```bash
docker compose -f docker-compose.yml -f docker-compose.build.yml up -d --build
```

## 🧭 Поведение

- Если ответ Remnawave содержит `total > size`, сервис догружает остальные
  страницы.
- На `401` от `/api/users` проверьте `REMNAWAVE_API_TOKEN`; ошибка логируется,
  job не падает.
- Telegram `429` логируется с `retry_after`, остальные пользователи продолжают
  обрабатываться.
- При заданном `TELEGRAM_ADMIN_ID` бот ведёт long polling `callback_query` и
  `message`, чтобы обрабатывать inline-кнопки и все команды.
- Дедупликация — точное совпадение оставшихся дней (`7/3/1`) на дату запуска.

## 📦 Развёртывание своей копии

Чтобы разместить бота в своём репозитории GitHub (чтобы установщик в одну строку
работал для вас), запушьте проект в **публичный** репозиторий:

```bash
git remote add origin https://github.com/<вы>/<репозиторий>.git
git push -u origin main
```

Затем замените `Nakedjustice/remnaWake` (и ветку `main`) в `get.sh`, `README.md`
и `README.ru.md`, а также путь `module` в `go.mod`. Файл `.env` в `.gitignore` и
никогда не пушится.

Workflow `.github/workflows/docker-publish.yml` публикует готовый образ в **ваш**
GHCR (`ghcr.io/<вы>/<репозиторий>`, в нижнем регистре) при каждом пуше в `main`.
Обновите строку `image:` в `docker-compose.yml`, а пакет сделайте публичным в
настройках **Packages** репозитория, чтобы пользователи могли скачивать без
авторизации. До этого можно собирать из исходников через
`docker-compose.build.yml`.

Проверьте, что установщик доступен:

```bash
curl -fsSL https://raw.githubusercontent.com/<вы>/<репозиторий>/main/get.sh | head -5
```
