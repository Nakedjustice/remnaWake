# 🌙 remnaWake

[English](README.md) · **Русский**

Лёгкий Go-сервис, который раз в сутки опрашивает панель
[Remnawave](https://remna.st) и напоминает пользователям в Telegram об истечении
подписки (за 7 / 3 / 1 день). Администратор может прямо из чата подтвердить
оплату — и бот продлит подписку на выбранное число месяцев.

> **Требуется панель Remnawave `v3.0.0` или новее.** В панели v3 у пользователей
> удалено поле `uuid`, теперь они идентифицируются числовым `id` — remnaWake
> обращается к панели именно по нему. Режима совместимости с v2 нет: сначала
> обновите панель, затем remnaWake. Существующая база бота переносится без
> изменений: числовой id панели уже хранился рядом с каждой заявкой на оплату и
> снимком для напоминаний.

## ✨ Возможности

- ⏰ **Напоминания** за 7 / 3 / 1 день до окончания плюс **возвращающие**
  сообщения через 1 и 3 дня *после* окончания (`WINBACK_DAYS` / `WINBACK_ENABLED`).
- 💳 **Подтверждение оплаты** — пользователь нажимает **«Я оплатил»**, админ
  подтверждает, бот продлевает подписку через `PATCH /api/users`. Опционально —
  автоматическая онлайн-оплата через **Platega** (СБП / карты) и/или
  **Telegram Stars** (⭐).
- 👤 **Личный кабинет** (`/me`) — привязанные профили, статус, срок, ссылка на
  подписку, сводка подарков/приглашений и быстрые действия.
- 🔗 **Самостоятельная привязка** (`/register`) — вставьте ссылку на подписку или
  имя профиля, и бот привяжет ваш Telegram ID без участия админа.
- 🛡️ **Защита от скам-регистраций** — первый `/start` от имени или ника, похожего
  на сотрудника (`support`, `admin`, верификация, имя бота и русские аналоги),
  локально блокируется. Пользователь может открыть встроенный чат поддержки,
  а каждый админ получает кнопку **«Разблокировать»** для ложных срабатываний.
- 🎁 **Подарки** (`/gift`, `/mygifts`) — купить подписку как передаваемый
  одноразовый код / deep-link `t.me`; получатель активирует сам.
- ➕ **Приглашения** (`/invite`) — подписчики запрашивают новый аккаунт в панели;
  админ одобряет, и ссылка на подписку отправляется обратно.
- 🎁 **Бесплатный пробный период** (`/trial` или мини-приложение, опционально) —
  новый пользователь без привязанного профиля один раз создаёт пробный профиль
  с настраиваемыми сроком, общим лимитом трафика, лимитом устройств и отдельным
  сквадом (`TRIAL_ENABLED`). Админ может менять все настройки в реальном времени
  из меню бота или админ-панели мини-приложения. Имя нового профиля должно
  содержать 3–36 ASCII-символов: латинские буквы, цифры, `_` или `-`, без пробелов.
- 🎉 **Реферальный бонус** (опционально) — одобренное приглашение начисляет
  бонусные дни пригласившему и/или приглашённому (`REFERRAL_ENABLED`).
  Настраивается в реальном времени из меню бота и админ-панели мини-приложения.
- 🔔 **Настройки уведомлений** — пользователи независимо отключают напоминания об
  окончании и сообщения о возврате через кнопку **🔔 Уведомления** в боте или в
  кабинете мини-приложения.
- 🗂 **Обращения в поддержку** — вместо одной бесконечной переписки у
  пользователя список отдельных обращений с темой и историей: открыть новое,
  ответить в конкретное, закрыть завершённое. У админа появляется входящая
  🛟 **Обращения** в `/admin` и в мини-приложении с ответом в нужную ветку.
  Чужое обращение неотличимо от несуществующего.
- 📱 **Слоты устройств** (`/devices`) — видно, какие устройства занимают слоты
  HWID (платформа, модель, дата подключения), и любой слот можно освободить
  самостоятельно, не обращаясь к админу. Каждый привязанный профиль показан
  отдельно, перед отвязкой запрашивается подтверждение, а незаданный лимит
  отображается как `n / ∞`.
- 📊 **Статистика** (`/stats`) — пользователи панели, оплаты и выручка за 30 дней,
  подарки, приглашения.
- 🖥 **Мини-приложение Telegram** — веб-версия кабинета (задайте `WEBAPP_URL`).
- 🗃 **Надёжность** — каждое уведомление дедуплицируется в SQLite (без повторов
  при перезапуске), неудачные отправки повторяются, Telegram `429` ретраится.
- 🌍 **Русский или английский** интерфейс (`BOT_LANG`, по умолчанию русский).
- 🐳 Distroless multi-stage Docker-образ, `restart: unless-stopped`,
  структурированные JSON-логи в stdout.

## 🔔 Уведомления

```
⏰ ivan, ваша подписка истекает 17.06.2026 — через 7 дней.
Для продления оплатите подписку.
```

В каждом сообщении указывается **имя профиля** Remnawave и **точная дата**
окончания (`ДД.ММ.ГГГГ`); слово «день/дня/дней» согласуется с числом.
Уведомляются только пользователи `ACTIVE` с `telegramId`; аккаунты `DISABLED` /
`LIMITED` не беспокоятся.

Если задан `TELEGRAM_ADMIN_ID` (используйте **Telegram user ID** администратора,
а не chat ID группы/канала), к сообщению добавляется inline-кнопка
**«Я оплатил»**. Каждое напоминание записывается в SQLite до отправки, поэтому
перезапуск не приведёт к повторному сообщению; неудачные отправки повторяются
при следующем ежедневном запуске.

**Возврат после окончания (win-back)** — если подписка истекла (статус `EXPIRED`
или `ACTIVE` с датой в прошлом), бот отправляет возвращающее сообщение с той же
кнопкой через 1 и 3 дня; подтверждение продлевает от `max(сейчас, старый срок)`.

```
⛔️ ivan, ваша подписка истекла 10.06.2026.
Чтобы продолжить пользоваться сервисом, продлите подписку.
```

## 💳 Подтверждение оплаты (опционально)

Активно только при заданном `TELEGRAM_ADMIN_ID`:

1. Пользователь нажимает **«Я оплатил»**. Если заданы **реквизиты**
   (`/setrequisites`), бот сначала отправляет их (например, карта / СБП).
2. Если заданы тарифы, бот показывает варианты месяцев/цен (`1 мес. — 150₽`, …);
   иначе — запасной вариант на 1 месяц.
3. **Администратор** получает данные клиента и выбранные месяцы/цену с кнопкой
   **«Подтвердить оплату»**.
4. После подтверждения бот вызывает `PATCH /api/users` и обычно продлевает на
   выбранные месяцы от `max(сейчас, текущий срок)`. При переходе на более
   дорогой тариф оставшееся активное время сначала пересчитывается по
   соотношению старой и новой месячной цены.
   Перед сменой тарифа пользователь дополнительно подтверждает действие: при
   апгрейде видит пересчитанный срок, при даунгрейде — предупреждение, что
   время не пересчитывается, а новые лимиты применятся сразу после подтверждения
   оплаты.

Цены **информационные** — в режиме P2P бот не проводит платежи; пользователь
платит вам внешним способом, а вы подтверждаете вручную.

### ⚡ Автоматические провайдеры: Platega и Telegram Stars (опционально)

Кроме P2P можно включить шлюз **Platega** (СБП / карты) и/или **Telegram Stars**
(встроенная валюта Telegram, XTR) для *автоматической* онлайн-оплаты. Включайте
любую комбинацию на лету — пункт **💳 Способы оплаты** в меню `/admin` или выбор
в админ-панели Mini App. **Можно включить несколько сразу**; если включено
больше одного, пользователь выбирает способ при оплате.

- 🏦 **Platega** — задайте `PLATEGA_MERCHANT_ID` + `PLATEGA_SECRET` (см.
  `.env.example`). После выбора тарифа пользователь получает ссылку **«Оплатить»**
  и кнопку **«🔄 Проверить оплату»**; Platega вызывает вебхук
  `POST /platega/callback` (тот же HTTP-сервер, что и Mini App — укажите этот URL
  как адрес уведомлений в кабинете Platega), бот заново проверяет статус и
  продлевает подписку.
- ⭐ **Telegram Stars** — задайте `TELEGRAM_STARS_ENABLED=true` и
  `TELEGRAM_STARS_RATE` (единиц цены за одну звезду; списывается
  `ceil(цена / rate)` звёзд), затем включите в админ-выборе **Способы оплаты**.
  Не нужны ни дополнительные ключи, ни вебхук — используется токен самого бота, и
  бот отправляет нативный счёт Telegram (валюта `XTR`) прямо в чат (в Mini App
  открывается встроенная форма оплаты). Подтверждение приходит через `getUpdates`
  (`pre_checkout_query` → `successful_payment`).

Все подтверждения **идемпотентны** — повторные вебхуки, нажатия или события
оплаты не продлевают подписку дважды.

### 📸 Чек об оплате (опционально)

Переключатель **«📸 Чек об оплате»** в `/admin` или Mini App требует
подтверждение оплаты: после выбора тарифа пользователь прикрепляет чек до
создания заявки; администратор получает её с вложением и обычными кнопками
подтверждения/отказа. Этот шаг работает и в чате, и прямо в Mini App. Для
JPEG/PNG действует лимит 10 МБ, для PDF, WebP и HEIC — 50 МБ. Шаг истекает через
10 минут (`/cancel` отменяет его в чате).

## ⌨️ Команды

**Пользователь** (доступны всем, кто пишет боту):

| Команда     | Что делает                                                    |
| ----------- | ------------------------------------------------------------- |
| `/start`    | Приветственное сообщение + инструкция по привязке             |
| `/me`       | Личный кабинет: статус, ссылка, подарки/приглашения, действия |
| `/menu` · `/help` | Открыть меню с inline-кнопками                          |
| `/tariff`   | Показать текущие тарифы/цены                                  |
| `/gift`     | Купить подарочную подписку и получить код (для подписчиков)   |
| `/mygifts`  | Список подарочных кодов, их статус и повторная отправка ссылки |
| `/invite`   | Пригласить нового пользователя в панель (для подписчиков)     |
| `/register` | Привязать Telegram к существующему профилю Remnawave          |
| `/devices`  | Устройства по каждому профилю; освободить слот HWID самому    |
| `/cancel`   | Отменить текущий шаг `/gift` / `/invite` / `/register`        |

**Администратор** (только `TELEGRAM_ADMIN_ID`; для остальных молча игнорируются):

| Команда                       | Что делает                  |
| ----------------------------- | --------------------------- |
| `/tariffs`                    | Список тарифов              |
| `/settariff <месяцев> <цена>` | Добавить или обновить тариф |
| `/deltariff <месяцев>`        | Удалить тариф               |
| `/setrequisites`              | Задать реквизиты, показываемые после «Я оплатил» (в два шага) |
| `/requisites`                 | Показать сохранённые реквизиты |
| `/stats`                      | 📊 Пользователи панели, оплаты и выручка за 30 дней, заявки, подарочные коды, приглашения |
| `/pending`                    | 🚨 Центр действий: ожидающие оплаты/подарки/приглашения/триалы с кнопками ✅/❌, плюс предупреждения панели, прокси, серверов и обновлений |
| `/backup`                     | 📦 Прислать ZIP-архив с резервной копией базы данных бота в личку |

В меню **`/admin`** также есть резервная копия базы в один тап, 📊 статистика, браузер 🎁 подарочных кодов (по
покупателю → использованы/не использованы → сами коды, с отзывом в один тап) и
выбор 🛡 **сквада по умолчанию** для новых пользователей из `/gift` и `/invite`
(откат на стоковый `Default-Squad`; если сквад не найден, создание завершается
видимой ошибкой). Те же элементы есть в админ-панели Mini App.

Раздел статистики Mini App также показывает выручку, конверсию, динамику по дням
и разбивку по способам оплаты за 7/30/90 дней. Там доступна история продлений
через P2P, Platega и Telegram Stars с поиском, фильтрами, постраничной навигацией
и идентификаторами транзакций платёжного провайдера, если они есть. На той же
странице есть локальная аналитика из SQLite: выручка подписок, дополнительного
трафика, подарков и приглашений, продления, локальные сигналы оттока/winback,
конверсия рефералов, воронка подарков, проданные гигабайты и микс провайдеров.
История объединяет платежи, подарочные коды и приглашения в один список: его можно
фильтровать по типу (платежи / подарки / приглашения) и удалять любую запись
(удаление затрагивает только локальную историю — оно не отменяет уже применённые
изменения в панели, а удаление неактивированного подарочного кода делает его
недействительным).

- 👤 **Управление пользователем** — найдите пользователя панели по **имени
  профиля** или **ссылке на подписку** и редактируйте его напрямую: продлите или
  сократите срок (±30/±90 дней или точное число), задайте лимит устройств
  (HWID), лимит трафика в GB (0 — без ограничения), стратегию сброса трафика,
  добавьте/уберите внутренние сквады, а также **отключите или включите**
  подписку — не открывая панель Remnawave. В Mini App это отдельная страница с
  таблицей всех пользователей панели и поиском; в боте поиск по имени или ссылке.
- 🔄 **Сброс трафика (новые)** — выберите стратегию сброса трафика
  (`NO_RESET` / `DAY` / `WEEK` / `MONTH`) для **вновь создаваемых** пользователей
  (`/gift`, `/invite`); существующие пользователи не затрагиваются.

Оба пункта доступны в `/admin` и в админ-панели Mini App.

Тарифы и состояние оплат хранятся в SQLite (`DB_PATH`, по умолчанию
`/data/bot.db`, в Docker-томе `botdata`), поэтому переживают перезапуск.

**Защита** — подтверждать оплату, одобрять приглашения/подарки, отзывать коды и
управлять тарифами может только админ; подтверждение оплаты идемпотентно; для
того же тарифа новый срок = `max(сейчас, текущий срок) + выбранные месяцы`, а
переход на более дорогой тариф сначала пересчитывает оставшееся активное время
по цене, чтобы дешёвые месяцы не превращались в полноценные дорогие месяцы;
даунгрейды не пересчитывают уже оплаченное время и сразу после подтверждения
оплаты применяют лимиты более дешёвого тарифа.

## 🎁 Подарки (`/gift`)

Получателя знать заранее не нужно — покупатель получает передаваемый код:

1. Отправьте `/gift` (или нажмите **🎁 Подарить подписку**); бот покажет реквизиты
   и кнопки тарифов.
2. Выберите период → админ получит заявку с **«✅ Подтвердить оплату»** /
   **«❌ Отклонить»**.
3. После подтверждения покупатель получает одноразовый код и deep-link
   `https://t.me/<бот>?start=gift_<КОД>`.
4. Получатель открывает ссылку (или отправляет `/start gift_<КОД>`): существующий
   привязанный профиль **продлевается**; иначе бот спрашивает имя пользователя,
   **создаёт** профиль, привязывает Telegram и присылает ссылку на подписку (срок
   идёт с момента активации). Имя нового профиля должно содержать 3–36
   ASCII-символов: латинские буквы, цифры, `_` или `-`, без пробелов.
5. Покупатель получает уведомление об активации.

Каждый код строго **одноразовый** (атомарная отметка в базе — без двойного
списания), переживает перезапуск и действует до активации или отзыва. Команда
`/gift` доступна только подписчикам; каждая покупка подтверждается админом.
Проверка в любой момент через `/mygifts` (**📦 Мои подарки**) — у выданных кодов
есть кнопка **🔗** для повторной отправки потерянной ссылки.

## ➕ Приглашения (`/invite`)

Любой подписчик может запросить новый аккаунт Remnawave:

1. Отправьте `/invite`.
2. Введите желаемое **имя пользователя** (3–36 ASCII-символов: латинские буквы,
   цифры, `_` или `-`; без пробелов).
3. Бот покажет стоимость (тариф на 1 месяц) и кнопку **«Отправить заявку»**
   (`/cancel` отменяет).
4. Админ получит **«✅ Одобрить»** / **«❌ Отклонить»**; при одобрении бот создаёт
   пользователя и отправляет ссылку на подписку пригласившему.

## 🔗 Привязка (`/register`)

Уже есть аккаунт Remnawave, но Telegram не привязан? Просто **вставьте ссылку на
подписку** в чат — без команд: бот найдёт профиль по короткому UUID
(`GET /api/users/by-short-uuid/{shortUuid}`) и предложит привязку. Явный
сценарий:

1. Отправьте `/register` (или нажмите **🔗 Привязать аккаунт**).
2. Отправьте **ссылку на подписку** или **имя профиля**. Поиск принимает любое
   имя, которое бот может создать, а также старые/импортированные имена в
   Unicode (буквы, цифры, `_` или `-`, 3–36 символов).
3. Бот найдёт аккаунт; если не привязан — попросит подтверждение.
4. Нажмите **«Привязать»** — бот вызовет `PATCH /api/users` и сразу привяжет вас.

Уже привязан к вам → подтверждается идемпотентно. Привязан к другому → отказ
(обратитесь к админу). Сессия истекает через 10 минут. При запуске бот
регистрирует меню команд через `setMyCommands`, поэтому появляется синяя кнопка
**Меню** и автодополнение по `/`.

## 🗂 Обращения в поддержку

Переписка с поддержкой разбита на отдельные обращения. **🗂 Мои обращения**
показывает список ваших обращений с темой и статусом; при открытии видна вся
история, а ответ уходит именно в эту ветку. **Закрыть** завершает обращение, но
не разговор — следующее написанное сообщение просто откроет новое.

Быстрый чат поддержки продолжает работать и по-прежнему пишет в самое свежее
открытое обращение, поэтому начатый разговор ничего не теряет.

Админу доступна входящая **🛟 Обращения** в `/admin` и в админ-панели
мини-приложения: в списке видны все обращения, а ответ адресуется той ветке, из
которой он пришёл, а не последнему сообщению пользователя. Запрос чужого
обращения возвращает ровно то же, что и запрос несуществующего, на любой
поверхности.

В мини-приложении можно дополнительно указать тему при создании обращения; в
боте тема берётся из первого сообщения. Все остальные операции на обеих
поверхностях идентичны.

## 📱 Слоты устройств (`/devices`)

У подписки есть лимит устройств HWID, и до сих пор пользователь, упёршийся в
него на новом телефоне, был вынужден просить админа освободить слот.
**📱 Мои устройства** показывает каждый привязанный профиль с занятыми и общими
слотами и перечисляет все устройства с платформой, моделью и датой первого
подключения из панели.

Открыть экран можно командой `/devices` (всегда), из кабинета мини-приложения
при заданном `WEBAPP_URL` или кнопкой в `/me`, когда он не задан: при
настроенном мини-приложении `/me` заменяет inline-кнопки входом в него — так же,
как уже сделано для продления и подарков.

Перед отвязкой запрашивается подтверждение, слот освобождается сразу, а
устройству придётся подключаться заново. Что стоит знать:

- Профили показаны **отдельно**, если к одному Telegram привязано несколько —
  бот никогда не выбирает первый молча.
- Лимит `0` означает «без ограничения»: мини-приложение показывает `n / ∞`, бот
  пишет, что лимит не задан. Просмотр и отвязка работают в обоих случаях —
  убрать устаревшее устройство полезно и без нехватки слотов.
- Если список устройств хотя бы одного профиля получить не удалось, весь экран
  сообщает о недоступности панели: неполный список занижает число занятых слотов
  и указал бы не на то устройство.
- При `DRY_RUN=true` отвязка только логируется, панель не изменяется.

## 🛡️ Защита от скам-регистраций

При первом `/start` или подписанном открытии Mini App бот локально блокирует имя или ник с паттернами
`support`, `admin`, `verif`, `official`, `moder`, `security`, `refund`, их
русскими аналогами или именем самого бота. Заблокированный пользователь получает
антиспам-экран с кнопкой **«Связаться с поддержкой»** в Mini App; встроенные
support-эндпоинты остаются доступными. Админам приходит алерт с кнопкой
**«Разблокировать»**; после ручной разблокировки повторный `/start` или открытие
Mini App не заблокирует человека снова. Имена профилей в HTML-форматированных
напоминаниях экранируются. В **меню администратора → 🛡 Антискам-паттерны** или
**Mini App → Админ → Настройки → 🛡 Антискам-регистрации** можно добавить или
удалить до 32 собственных паттернов без учёта регистра; в Mini App также виден
список активных блокировок и доступна ручная разблокировка.

## 🔄 Автообновление (опционально)

При `AUTOUPDATE_ENABLED=true` бот периодически проверяет реестр на новую версию
`AUTOUPDATE_IMAGE` и присылает всем админам сообщение с кнопками
**🔄 Установить сейчас** / **Позже** (интервал `AUTOUPDATE_CHECK_INTERVAL`, по
умолчанию `6h`).

Поскольку бот работает как distroless-контейнер без привилегий, **установка в
один тап** делегируется sidecar-контейнеру
[Watchtower](https://github.com/nicholas-fedor/watchtower) в режиме HTTP-API по
триггеру.
`install.sh configure` может сгенерировать сервис Watchtower в
`docker-compose.override.yml`, задать `AUTOUPDATE_ENABLED=true`,
`WATCHTOWER_URL=http://watchtower:8080` и создать общий `WATCHTOWER_TOKEN`. По
кнопке **Установить сейчас** бот шлёт POST на `/v1/update` Watchtower; доступ к
Docker-сокету есть только у Watchtower. Если `WATCHTOWER_URL` пустой — режим
«только уведомления» с командой `docker compose pull && docker compose up -d`.

Сгенерированный сервис Watchtower использует `nickfedor/watchtower:latest` и
`pull_policy: always`. Исходный образ `containrrr/watchtower` заархивирован
авторами в декабре 2025 года и больше не работает с актуальными демонами
Docker, поэтому установки генерируются на поддерживаемом форке: он читает те же
переменные `WATCHTOWER_HTTP_API_*` и отдаёт тот же эндпоинт `/v1/update`.
`DOCKER_API_VERSION` намеренно не задаётся — Watchtower сам согласует версию API
с демоном на хосте; именно закреплённая версия и оставила старый sidecar позади
новых демонов.

**Существующие установки нужно перевести:** `./install.sh doctor` предупредит,
если в override всё ещё прописан `containrrr/watchtower` или `DOCKER_API_VERSION`.
Заново запустите `./install.sh configure`, затем `docker compose up -d watchtower`.

## 🩺 Мониторинг прокси Xray Checker (опционально)

Подключает [xray-checker](https://github.com/kutovoys/xray-checker) как
дополнительный контейнер, чтобы админы видели, работают ли прокси, через которые
подключаются пользователи. Sidecar проверяет связь через каждый конфиг
VLESS/VMess/Trojan/Shadowsocks из подписки и публикует результат на эндпоинте
Prometheus `/metrics` (порт `2112`).

`install.sh configure` умеет включить это: спрашивает URL подписки для проверки,
генерирует креды basic-auth, ставит `XRAY_CHECKER_URL=http://xray-checker:2112` и
дописывает сервис `xray-checker` в `docker-compose.override.yml`. Контейнеры в
одной сети compose-проекта, поэтому бот обращается к чекеру по имени — публичный
порт не нужен.

Когда `XRAY_CHECKER_URL` задан, бот добавляет кнопку **🩺 Состояние прокси** в меню
`/admin` и страницу **Состояние прокси** в админ-панель Mini App (каждый прокси —
✅ доступен с задержкой или ❌ недоступен), опрашивает чекер каждые
`XRAY_CHECKER_POLL_INTERVAL` (по умолчанию `2m`) и пишет каждому админу, когда
прокси **падает** или **восстанавливается** (с дедупликацией между перезапусками).
Оставьте `XRAY_CHECKER_URL` пустым, чтобы отключить (значение по умолчанию).

Отдельно бот пишет админам, когда **перестаёт отвечать сам чекер**: после трёх
неудачных опросов подряд (около 6 минут на интервале по умолчанию), с текстом
ошибки, и ещё раз — когда опрос восстановится. Без этого сломанный сайдкар не
виден нигде, кроме логов: мониторинг молча прекращается, а последние известные
состояния прокси продолжают выглядеть здоровыми.

Если такое уведомление пришло, быстрее всего разбираться через
`./install.sh doctor`: он проверяет сервис сайдкара, креды и — самая частая
причина **404** на `/metrics` — что `METRICS_BASE_PATH` в
`docker-compose.override.yml` всё ещё совпадает с `XRAY_CHECKER_BASE_PATH` в
`.env`. Когда они разошлись, чекер отдаёт метрики в корне, а бот опрашивает
несуществующий под-путь.

### Полноценная веб-панель

Вкладка прокси в Mini App намеренно компактная. У xray-checker есть собственная
просторная веб-панель, и вы можете дать админам открывать её из бота или браузера,
задав **`XRAY_CHECKER_PUBLIC_URL`** — адрес, по которому эта панель доступна. Тогда
бот добавляет кнопку **🌐 Веб-панель прокси** в меню `/admin` и на карточку
состояния прокси, а также кнопку **Открыть полную панель** на вкладку прокси в
Mini App. Ссылка не зависит от `XRAY_CHECKER_URL` и работает даже без опроса
`/metrics`. Панель остаётся только для админов, потому что закрыта тем же
basic-auth, что и `/metrics` (`METRICS_PROTECTED=true`): браузер запросит креды
чекера, вход через Telegram не нужен.

`install.sh configure` автоматизирует публикацию. Если чекер включён, установщик
спрашивает *«Expose the Xray Checker web dashboard at a public URL?»*:

- **На том же домене, что и Mini App** (если задан `WEBAPP_URL`): панель отдаётся
  по под-пути (по умолчанию `/checker`, то есть панель доступна на `…/checker/`).
  Установщик задаёт `METRICS_BASE_PATH` sidecar'а, дописывает префикс в
  `XRAY_CHECKER_URL` (чтобы опрос `/metrics` продолжал работать) и — если бот за
  Caddy от Remnawave — сам добавляет маршрут в сайт Caddy (встраивая его в уже
  существующий сайт бота, если он есть):

  ```caddy
  https://bot.example.com {
      redir /checker /checker/
      handle /checker/* {
          reverse_proxy remnaWake-xray-checker:2112
      }
      reverse_proxy remnaWake-bot:8080
  }
  ```

  Префикс сохраняется на upstream (совпадает с `METRICS_BASE_PATH`), а голый
  `/checker` редиректится на `/checker/`, потому что именно там sidecar отдаёт
  панель. За хостовым nginx/Caddy установщик публикует `127.0.0.1:<порт>:2112` и
  печатает готовый блок `location` с редиректом.
- **Свой домен** (без Mini App): вы вводите полный публичный URL и сами
  настраиваете реверс-прокси на sidecar; панель отдаётся в корне этого хоста.

## 🖥 Мини-приложение Telegram

Если задан `WEBAPP_URL`, бот поднимает мини-приложение «Личный кабинет» и
регистрирует его как **кнопку меню** чата (плюс кнопка «🖥 Открыть
мини-приложение» внутри `/me`). В нём видны привязанные профили, статус и срок,
ссылка на подписку с копированием в один тап, реквизиты, сводка подарков и
приглашений. Прямо в Mini App доступны привязка профиля, активация подарочного
кода, загрузка чека и ручная проверка платежа Platega, поэтому весь сценарий
продления можно завершить без перехода в чат.
Переключатель языка 🇷🇺/🇬🇧 (вверху справа) по умолчанию берёт язык Telegram
пользователя (с откатом к `BOT_LANG`) и запоминает явный выбор.

Админам также доступна страница **«Статистика»**, совпадающая с `/stats`: общие
счётчики и статусы пользователей панели, подтверждённые оплаты и выручка за 30
дней, счётчики подарочных кодов и ожидающие приглашения. Вверху админ-хаба есть
доступный только для чтения **Action Center**: он собирает ожидающие очереди,
истекающих или почти исчерпавших трафик пользователей,
прокси/инфраструктуру/провайдеров и последний известный статус обновлений, а
каждый пункт ведёт в уже существующий детальный раздел.

**Что нужно** — мини-приложение раздаёт сам бот на `WEBAPP_LISTEN` (по умолчанию
`:8080`). Telegram открывает мини-приложения только по **HTTPS**, поэтому
поставьте впереди реверс-прокси (nginx / Caddy / Traefik) и укажите в
`WEBAPP_URL` публичный HTTPS-адрес. Для прокси на хосте установщик публикует
`127.0.0.1:${WEBAPP_HOST_PORT}:8080` (порт хоста по умолчанию `8080`); если
выбрали другой порт, используйте его в `proxy_pass` / `reverse_proxy`. Запросы
аутентифицируются проверкой Telegram `initData` (HMAC-подпись токеном бота) —
дополнительные секреты не нужны.

### Шаблоны для реверс-прокси

В обоих шаблонах замените `bot.example.com` на свой домен.

**Caddy** (`/etc/caddy/Caddyfile`) — TLS выпускается автоматически:

```caddyfile
bot.example.com {
    reverse_proxy 127.0.0.1:8080
}
```

**nginx** (`/etc/nginx/sites-available/remnawake-webapp`) — предполагаются
сертификаты certbot (`certbot --nginx -d bot.example.com`):

```nginx
server {
    listen 443 ssl;
    http2 on;
    server_name bot.example.com;

    ssl_certificate     /etc/letsencrypt/live/bot.example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/bot.example.com/privkey.pem;

    location / {
        proxy_pass http://127.0.0.1:8080;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}

server {
    listen 80;
    server_name bot.example.com;
    return 301 https://$host$request_uri;
}
```

```bash
sudo ln -s /etc/nginx/sites-available/remnawake-webapp /etc/nginx/sites-enabled/
sudo nginx -t && sudo systemctl reload nginx
```

### Рядом с remnawave (Caddy в контейнере)

Если у вас уже работает [remnawave](https://remna.st) со своим Caddy **в
контейнере**, не используйте `127.0.0.1:8080` — внутри контейнера Caddy этот
адрес указывает на сам Caddy. Бот должен быть доступен по **имени контейнера**
через общую сеть.

**1. Подключите бота к сети remnawave** (без блока `ports:`). Установщик пишет
это в `docker-compose.override.yml`; полная форма выглядит так:

```yaml
services:
  bot:
    image: ghcr.io/nakedjustice/remnawake:main
    pull_policy: always
    container_name: remnaWake-bot
    restart: unless-stopped
    env_file:
      - ./.env
    environment:
      DB_PATH: /data/bot.db
    volumes:
      - botdata:/data
    networks:
      - remnawave-network

networks:
  remnawave-network:
    name: remnawave-network
    external: true

volumes:
  botdata:
```

**2. Добавьте сайт в существующий `Caddyfile`**:

```caddyfile
https://bot.example.com {
    reverse_proxy remnaWake-bot:8080
}
```

**3. Укажите этот адрес в `WEBAPP_URL`** в `.env`, затем поднимите бота и
перезагрузите Caddy (сначала убедитесь, что DNS указывает на сервер, иначе Caddy
не выпустит сертификат):

```bash
docker compose up -d            # в каталоге remnaWake
docker compose restart caddy    # в каталоге caddy
```

| `REFERRAL_ENABLED`       | нет         | `false`           | Начислять бонусные дни за одобренные приглашения пригласившему и/или приглашённому |
| `REFERRAL_INVITER_BONUS_DAYS` | нет    | `30`              | Бонусные дни к подписке пригласившего за каждое одобренное приглашение |
| `REFERRAL_INVITEE_BONUS_DAYS` | нет    | `0`               | Дополнительные дни приглашённому сверх месячного срока приглашения |
| `DB_BACKUP_ENABLED`      | нет         | `false`           | Начальное состояние плановых бэкапов; сохранённая настройка из меню администратора имеет приоритет |
| `DB_BACKUP_INTERVAL_DAYS` | нет        | `1`               | Начальный интервал в днях (1–365, с ограничением); сохранённая настройка админа имеет приоритет |

## 🚀 Запуск

### Установка на сервер (рекомендуется)

Бот работает из готового образа GHCR, поэтому на сервер попадают только
`docker-compose.yml` и `.env`. Одна команда запускает интерактивный установщик,
который пишет их в **`/opt/remnaWake`** (нужны права root):

```bash
curl -fsSL https://raw.githubusercontent.com/Nakedjustice/remnaWake/main/get.sh | sudo bash
```

Установить в другое место (для доступного на запись пути root не нужен) — через
`TARGET_DIR`:

```bash
curl -fsSL https://raw.githubusercontent.com/Nakedjustice/remnaWake/main/get.sh | TARGET_DIR="$HOME/remnaWake" bash
```

Либо запустите установщик напрямую (ставит в текущий каталог, переопределяется
через `REMNAWAKE_DIR`):

```bash
mkdir -p ~/remnaWake && cd ~/remnaWake
curl -fsSL https://raw.githubusercontent.com/Nakedjustice/remnaWake/main/install.sh | bash
```

Сначала установщик спросит канал релиза. `main` — стабильный канал по умолчанию.
`dev` использует ветку разработки и образ
`ghcr.io/nakedjustice/remnawake-dev:latest`; перед выбором этого канала
установщик показывает предупреждение о нестабильности и просит подтвердить
решение. Затем он спросит URL панели, токены, ID администратора, таймзону, время
запуска, а также опциональные настройки Mini App, Platega, Stars, пробного
периода, рефералов и автообновления. При повторном запуске он подставляет
текущие значения из `.env`, сохраняет timestamp-бэкапы, пишет `.env` с правами
`600`, скачивает `docker-compose.yml`, а локальную топологию пишет в
`docker-compose.override.yml`. Нужны `curl` (либо `wget`) и Docker Engine с
плагином Compose — `git` не требуется.

Команды обслуживания:

```bash
./install.sh configure   # первая установка проходит все разделы; при наличии .env открывает меню
./install.sh menu        # сразу открыть меню перенастройки и изменить один раздел
./install.sh doctor      # read-only отчёт: актуальность установщика, маршруты, порты, compose, Watchtower, xray, бэкапы
./install.sh update      # сделать бэкап, скачать образ, перезапустить и обновить сам install.sh
./install.sh backup      # скопировать .env и compose-файлы в ./backups
./install.sh restore <backup.db>  # заменить базу данных бота файлом из бэкапа
```

`doctor` объясняет каждую находку: что обнаружено, какой инвариант ожидался и
какую команду обычно выполнить для исправления. Он ничего не переписывает; для
перегенерации файлов используйте `./install.sh configure`, для timestamp-бэкапов
конфига — `./install.sh backup`.

`update` скачивает не только образ, но и поддерживает актуальным сам `install.sh`:
сравнивает локальный файл с версией вашего канала выпуска и заменяет его (сделав
бэкап с меткой времени), если они разошлись; новая версия применяется со
следующего запуска. Это важно потому, что образ и установщик выпускаются из
одного коммита, но раньше скачивался только образ — админ мог месяцами гонять
старый установщик против свежего бота, с проверками `doctor` и генерацией
override, отставшими от него. То же сравнение `doctor` показывает без изменений
файла — в разделе **Installer**. Чтобы отключить самообновление (например, когда файл
разворачивается системой управления конфигурацией), задайте
`REMNAWAKE_SKIP_SELF_UPDATE=1`.

### 💾 Резервное копирование и восстановление базы данных

При `DB_BACKUP_ENABLED=true` бот во время ежедневного запуска отправляет каждому
админу в личку компактную копию своей базы SQLite
(`remnawake-backup-<дата>.db`), не чаще одного раза в `DB_BACKUP_INTERVAL_DAYS`
дней. Админ также может запросить ZIP-архив в любой момент командой `/backup`,
кнопкой в Telegram-меню `/admin` или в админ-разделе Mini App; бот отправит архив
в чат запросившего админа. Перед восстановлением извлеките из ZIP файл `.db`.
Значения окружения задают начальное расписание; включить или выключить бэкапы и
задать интервал можно как в **Меню администратора → 💾 Резервные копии**, так и в
админ-панели Mini App (**Настройки → 💾 Резервные копии**): пресеты 1/3/7/30 дней
либо любое значение от 1 до 365 дней. Сохранённые настройки имеют приоритет после
перезапуска. Включение или изменение активного интервала делает бэкап доступным
при следующем ежедневном запуске `RUN_AT`, не отправляя его сразу:

```bash
./install.sh restore /path/to/remnawake-backup-2026-07-05-0900.db
```

Восстановление останавливает бота, сохраняет текущую базу в
`./backups/bot.db.pre-restore.<timestamp>`, копирует бэкап в volume `botdata`,
очищает устаревшие WAL-файлы и снова запускает бота.

## 🧭 Поведение

- Если ответ Remnawave содержит `total > size`, сервис догружает остальные
  страницы.
- Поиск подписчика по Telegram ID идёт через курсорный
  `GET /api/users/stream?telegramId=…`: в панели v3 старый маршрут
  `by-telegram-id` удалён. Поиск по имени профиля и ссылке на подписку не
  изменился.
- На `401` от `/api/users` проверьте `REMNAWAVE_API_TOKEN`; ошибка логируется,
  job не падает.
- Telegram `429` логируется с `retry_after`, остальные пользователи продолжают
  обрабатываться.
- При заданном `TELEGRAM_ADMIN_ID` бот ведёт long polling `callback_query` и
  `message`, чтобы обрабатывать inline-кнопки и все команды.
- Дедупликация — точное совпадение оставшихся дней (`7/3/1`) на дату запуска.

## 📦 Развёртывание своей копии

Чтобы разместить бота в своём репозитории GitHub (чтобы установщик в одну строку
работал для вас), запушьте проект в **публичный** репозиторий:

```bash
git remote add origin https://github.com/<вы>/<репозиторий>.git
git push -u origin main
```

Затем замените `Nakedjustice/remnaWake` (и ветку `main`) в `get.sh`, `README.md`
и `README.ru.md`, а также путь `module` в `go.mod`. Файл `.env` в `.gitignore` и
никогда не пушится.

Workflow `.github/workflows/docker-publish.yml` публикует два независимых пакета
GHCR (имена приводятся к нижнему регистру):

- `main` → `ghcr.io/<вы>/<репозиторий>:latest` для стабильных установок;
- `dev` → `ghcr.io/<вы>/<репозиторий>-dev:latest` для тестирования до слияния.

Перед слиянием `dev` в `main` выберите dev-канал в установщике для тестовой
установки либо скачайте пакет вручную:

```bash
docker pull ghcr.io/<вы>/<репозиторий>-dev:latest
```

Если образы должны скачиваться без авторизации, сделайте оба пакета публичными в
настройках **Packages** репозитория. До этого можно собирать из исходников через
`docker-compose.build.yml`.

Проверьте, что установщик доступен:

```bash
curl -fsSL https://raw.githubusercontent.com/<вы>/<репозиторий>/main/get.sh | head -5
```
