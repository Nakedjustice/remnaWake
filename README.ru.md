# remnaWake

[English](README.md) · **Русский**

Лёгкий Go-сервис, который раз в сутки опрашивает панель
[Remnawave](https://remna.st) и уведомляет пользователей в Telegram об истечении
подписки (за 7 / 3 / 1 день). Дополнительно администратор может прямо из Telegram
подтвердить оплату — и бот продлит подписку на выбранное число месяцев.

## Возможности

- Один ежедневный запуск по cron (`go-co-op/gocron/v2`) в заданной таймзоне.
- Авторизация в Remnawave через API-токен панели (`Authorization: Bearer ...`).
- Получение пользователей `GET /api/users` с пагинацией по `start/size`.
- Обработка только `status == "ACTIVE"`, пользователи без `telegramId` пропускаются.
- **Возвращающие сообщения** через 1 и 3 дня *после* окончания подписки
  (настраивается через `WINBACK_DAYS` / `WINBACK_ENABLED`) с той же кнопкой
  оплаты.
- Каждое уведомление дедуплицируется в SQLite, поэтому перезапуски не приводят
  к повторным сообщениям; неудачные отправки повторяются при следующем
  ежедневном запуске, а ответы Telegram 429 (rate limit) ретраятся автоматически.
- **`/stats`** — отчёт для администратора: пользователи панели (активные /
  скоро истекают / истекшие / с привязкой), оплаты и выручка за 30 дней,
  подарки и приглашения.
- **Русский или английский** интерфейс чата через `BOT_LANG` (по умолчанию русский).
- Отправка сообщений через Telegram Bot API (`sendMessage`).
- Inline-кнопка **«Я оплатил»** в уведомлениях и подтверждаемый администратором
  сценарий продления подписки через `PATCH /api/users`.
- **`/register`** — самостоятельная привязка Telegram: пользователь отправляет
  ссылку на подписку (или имя профиля Remnawave) — достаточно просто вставить
  ссылку в чат, — бот находит аккаунт и привязывает Telegram ID без участия
  администратора.
- **`/invite`** — действующие подписчики могут запросить создание нового
  пользователя в панели; администратор одобряет, и бот отправляет ссылку на
  подписку обратно пригласившему.
- **`/gift`** — покупка подписки в подарок без указания получателя: после
  подтверждения администратором покупатель получает уникальный одноразовый код и
  deep-link `t.me`, который можно переслать кому угодно; открывший ссылку получает
  месяцы на свой профиль (или новый профиль, созданный на месте).
- **`/mygifts`** — список купленных подарочных кодов с их статусом (ожидает
  подтверждения / выдан / активирован / отклонён / отозван) и возможность заново
  получить сообщение со ссылкой активации, если оригинальное потерялось.
- **`/me`** — личный кабинет: привязанные профили со статусом и датой окончания,
  ссылка на подписку, сводка по подаркам/приглашениям и кнопки продления,
  подарка, приглашения и перепривязки. Также открывается постоянной кнопкой
  **«👤 Личный кабинет»** под полем ввода (ставится при `/start`); без привязки
  кабинет предлагает привязать аккаунт.
- Приветственное сообщение при команде `/start` с кнопкой **🔗 Привязать
  аккаунт**, которая проводит новых пользователей через привязку (и предупреждает,
  что без неё уведомления не приходят).
- **Мини-приложение Telegram** — веб-версия личного кабинета (профили, срок
  действия, ссылка на подписку, тарифы с кнопкой продления, подарки),
  открывается кнопкой меню чата; включается переменной `WEBAPP_URL` (см. ниже).
- Структурированные логи в stdout (`log/slog` JSON).
- Multi-stage Docker-образ на базе `distroless/static`, `restart: unless-stopped`.

## Текст уведомления

```
⏰ ivan, ваша подписка истекает 17.06.2026 — через 7 дней.
Для продления оплатите подписку.
```

В каждом сообщении указывается **имя профиля** Remnawave и **точная дата**
окончания (`ДД.ММ.ГГГГ`), чтобы получатель понял, какая именно подписка истекает.
Слово «день/дня/дней» согласуется с числом.

Если задан `TELEGRAM_ADMIN_ID`, к сообщению добавляется inline-кнопка
«Я оплатил». Используйте именно **Telegram ID администратора** (user ID), а не
chat ID группы/канала.

Каждое напоминание записывается в SQLite **до** отправки, поэтому перезапуск
бота (или совпадение запуска при старте с ежедневным запуском) не приведёт к
повторному сообщению; если отправка в Telegram не удалась, она повторится при
следующем ежедневном запуске.

### Возврат после окончания подписки (win-back)

Если подписка уже **истекла** (статус `EXPIRED` в панели или `ACTIVE` с датой
окончания в прошлом), бот отправляет возвращающее сообщение через 1 и 3 дня
после даты окончания:

```
⛔️ ivan, ваша подписка истекла 10.06.2026.
Чтобы продолжить пользоваться сервисом, продлите подписку.
```

К сообщению прикрепляется та же кнопка **«Я оплатил»**, а обычный сценарий
подтверждения продлевает подписку от `max(сейчас, старая дата окончания)`.
Аккаунты со статусом `DISABLED` / `LIMITED` не беспокоятся. Дни настраиваются
переменной `WINBACK_DAYS` (по умолчанию `1,3`), отключение —
`WINBACK_ENABLED=false`.

## Сценарий подтверждения оплаты (опционально)

Активен только при заданном `TELEGRAM_ADMIN_ID`:

1. Пользователь нажимает **«Я оплатил»** под уведомлением об истечении. Если
   администратор задал **реквизиты для оплаты** (см. `/setrequisites` ниже), бот
   сначала отправляет их пользователю (например, номер карты или данные СБП).
2. Если администратор задал тарифы, бот показывает на сообщении варианты
   месяцев и цен (например, `1 мес. — 150₽`, `3 мес. — 450₽`, плюс кнопка
   «← Назад»), и пользователь выбирает один. Если тарифы **не заданы**, работает
   запасной вариант — заявка на 1 месяц.
3. Бот отправляет **администратору** данные клиента и выбранные месяцы/цену с
   кнопкой **«Подтвердить оплату»**.
4. Администратор подтверждает. Бот вызывает `PATCH /api/users` (с `uuid` в теле
   запроса) и продлевает подписку на **выбранное число месяцев** (от
   `max(сейчас, текущий срок)`), затем сообщает новый срок действия.

Цены **информационные** — бот не проводит платежи. Пользователь платит вам
внешним способом, а вы подтверждаете вручную.

**Чек об оплате (опционально).** Администратор может требовать подтверждение
оплаты: переключатель **«📸 Чек об оплате»** в меню `/admin` или в
админ-панели мини-приложения. Когда включено, после выбора тарифа пользователь
должен отправить **фото, скриншот или PDF-файл** чека (банки часто выгружают
чеки в PDF; изображения, отправленные файлом без сжатия, тоже принимаются),
и только после этого создаётся заявка; администратор получает её
как сообщение с фото или документом и теми же кнопками подтверждения/отказа.
Другие типы файлов отклоняются с подсказкой. Подпись к чеку пересылается
администраторам; `/cancel` работает и в подписи. Шаг ожидания чека истекает через
10 минут (`/cancel` отменяет его); если чек приходит позже, бот сообщает, что
нужно начать продление заново. Продление, начатое из мини-приложения,
продолжается в чате с ботом на этом шаге. При выключенном переключателе
сценарий не меняется.

### Команды

**Команды пользователя** (доступны всем, кто пишет боту):

| Команда       | Что делает                                                              |
| ------------- | ----------------------------------------------------------------------- |
| `/start`      | Показать приветственное сообщение                                       |
| `/me`         | Личный кабинет: статус подписки, ссылка, подарки/приглашения, действия  |
| `/menu`       | Открыть меню с inline-кнопками                                          |
| `/tariff`     | Показать текущие тарифы/цены                                            |
| `/gift`       | Купить подарочную подписку и получить код/ссылку (только для подписчиков) |
| `/mygifts`    | Список купленных подарочных кодов, их статус и повторная отправка ссылки |
| `/invite`     | Пригласить нового пользователя в панель (только для подписчиков)        |
| `/register`   | Привязать свой Telegram к существующему профилю Remnawave               |
| `/cancel`     | Отменить текущий шаг `/gift`, `/invite` или `/register`                 |
| `/help`       | То же, что `/menu`                                                       |

**Команды администратора** (только аккаунт с ID, равным `TELEGRAM_ADMIN_ID`; для
остальных молча игнорируются):

| Команда                       | Что делает                  |
| ----------------------------- | --------------------------- |
| `/tariffs`                    | Список тарифов              |
| `/settariff <месяцев> <цена>` | Добавить или обновить тариф |
| `/deltariff <месяцев>`        | Удалить тариф               |
| `/setrequisites`              | Задать реквизиты для оплаты, которые показываются пользователю после «Я оплатил» (в два шага: команда, затем текст следующим сообщением) |
| `/requisites`                 | Показать текущие сохранённые реквизиты |
| `/stats`                      | 📊 Статистика: пользователи панели (всего / активных / истекают за 7 дней / истекших / с привязанным Telegram), оплаты за 30 дней с суммой, заявки в ожидании, подарочные коды по статусам, приглашения |

В меню `/admin` также есть кнопка **«📊 Статистика»** (тот же отчёт, что и
`/stats`), раздел **«🎁 Подарочные коды»** со списком всех выданных (ещё не
активированных) кодов и кнопкой отзыва для каждого, а также пункт
**«🛡 Сквад по умолчанию»** — выбор внутреннего сквада панели, в который
добавляются новые пользователи, создаваемые через `/gift` и `/invite`. Пока
сквад не выбран, используется сквад с именем `Default-Squad` (создаётся при
установке Remnawave); если не найден ни тот, ни другой, создание пользователя
завершается видимой ошибкой, а не профилем без доступа к серверам. Тот же
выбор доступен в админ-панели Mini App.

Тарифы и состояние оплат хранятся в SQLite (`DB_PATH`, по умолчанию
`/data/bot.db`, в Docker-томе `botdata`), поэтому переживают перезапуск.

### Кнопки меню

По команде `/menu` (или `/help`) бот присылает пять inline-кнопок:

| Кнопка                        | Действие                                     |
| ----------------------------- | -------------------------------------------- |
| 💵 Тарифы                    | Показать текущие цены                        |
| 🎁 Подарить подписку          | Начать сценарий подарочной подписки          |
| 📦 Мои подарки                | Список ваших подарочных кодов и их статус    |
| 👤 Пригласить пользователя    | Начать сценарий приглашения нового           |
| 🔗 Привязать аккаунт          | Начать привязку Telegram к профилю           |

### Подписка в подарок (`/gift`)

Для подарка не нужно знать получателя заранее — покупатель получает передаваемый
код (это покрывает и оплату за другого пользователя: просто перешлите ему
ссылку):

1. Отправьте боту `/gift` (или нажмите **🎁 Подарить подписку** в меню). Бот
   покажет реквизиты для оплаты (если заданы) и кнопки тарифов.
2. Выберите период. Администратор получит заявку с кнопками
   **«✅ Подтвердить оплату»** и **«❌ Отклонить»**.
3. После подтверждения покупатель получает уникальный одноразовый код и ссылку
   вида `https://t.me/<бот>?start=gift_<КОД>` — её можно переслать кому угодно.
4. Получатель открывает ссылку (или отправляет `/start gift_<КОД>`):
   - если у него уже есть профиль, привязанный к Telegram, — он **продлевается**
     на подаренные месяцы (при нескольких профилях бот предложит выбрать);
   - если профиля нет — бот спросит желаемое имя пользователя, **создаст** новый
     профиль в панели, привяжет Telegram ID и пришлёт ссылку на подписку. Срок
     подписки начинает идти с момента активации, а не покупки.
5. Покупатель получает уведомление, когда подарок активирован.

Каждый код строго **одноразовый** (атомарная отметка в базе — параллельные
активации не приведут к двойному списанию), переживает перезапуск бота и действует
до активации или отзыва администратором. Команда `/gift` доступна только
действующим подписчикам; каждая покупка подтверждается администратором.

Покупатель в любой момент может проверить свои подарки командой `/mygifts` (или
кнопкой **📦 Мои подарки** в меню): бот покажет каждый купленный код и его статус —
ожидает подтверждения оплаты, выдан/ожидает активации, активирован (с именем
профиля получателя), отклонён или отозван. У выданных кодов есть кнопка **🔗**,
которая заново присылает сообщение со ссылкой активации, если оригинальное
потерялось. Получить ссылку может только сам покупатель.

### Приглашение нового пользователя (`/invite`)

Любой действующий подписчик может запросить создание нового аккаунта в панели:

1. Отправьте боту `/invite`.
2. Введите желаемое **имя пользователя** для нового участника (3–32 символа,
   буквы / цифры / нижнее подчёркивание).
3. Бот покажет стоимость (цена тарифа на 1 месяц) и кнопку **«Отправить заявку»**.
   `/cancel` отменяет.
4. Администратор получит заявку с кнопками **«✅ Одобрить»** и **«❌ Отклонить»**.
   При одобрении бот создаёт пользователя в панели и отправляет ссылку на подписку
   пригласившему.

Команда `/invite` доступна только действующим подписчикам; каждая заявка
подтверждается администратором.

### Привязка Telegram к профилю (`/register`)

Пользователи, у которых уже есть аккаунт Remnawave, но Telegram не привязан,
могут сделать это самостоятельно — без обращения к администратору. Самый
простой способ — просто отправить боту **ссылку на подписку**, без всяких
команд: бот найдёт профиль по короткому UUID в конце ссылки (через
`GET /api/users/by-short-uuid/{shortUuid}`) и предложит привязку.

Явный сценарий тоже принимает оба варианта:

1. Отправьте боту `/register` (или нажмите **🔗 Привязать аккаунт** в меню).
2. Отправьте **ссылку на подписку** или **имя профиля Remnawave** (и то и
   другое видно в VPN-приложении).
3. Бот найдёт аккаунт. Если профиль существует и Telegram ещё не привязан, бот
   попросит подтверждение.
4. Нажмите **«Привязать»** — бот вызовет `PATCH /api/users` и сразу привяжет
   ваш Telegram ID к профилю.

Если профиль уже привязан к вашему Telegram — бот подтвердит это идемпотентно.
Если привязан к чужому — откажет и попросит обратиться к администратору.
Сессия истекает через 10 минут бездействия.

**Как найти:** при запуске бот регистрирует меню команд (через `setMyCommands`),
поэтому у пользователей появляется синяя кнопка **Меню** и автодополнение по `/`
для всех команд выше. По команде `/menu` (или `/help`) бот пришлёт пять
inline-кнопок.

Защита:

- Подтверждать оплату, одобрять приглашения и подарки, отзывать подарочные коды
  и управлять тарифами может только заданный администратор.
- Подтверждение оплаты **идемпотентно**: повторные нажатия не продлят подписку дважды.
- Новый срок = `max(сейчас, текущий срок)` + выбранные месяцы, поэтому позднее
  подтверждение не оставит дату в прошлом.

## Приветственное сообщение

При отправке команды `/start` бот отправляет сообщение со списком своих функций
и пошаговой инструкцией по привязке аккаунта (нет привязки — нет уведомлений),
а также inline-кнопку **🔗 Привязать аккаунт**, запускающую тот же сценарий,
что и `/register`:

```
👋 Привет! Я бот для управления вашей подпиской. Вот что я умею:

⏰ Напоминания — предупрежу об окончании подписки за 7, 3 и 1 день.
💳 Продление — после оплаты нажмите «Я оплатил» под напоминанием, и администратор подтвердит продление.
👤 Личный кабинет — статус подписки, ссылка и подарки: /me.
🎁 Подарок (/gift) — подарить подписку человеку, у которого есть Telegram: он сам активирует подарок в этом боте.
➕ Приглашение (/invite) — оформить подписку тому, у кого нет Telegram или кто не может им пользоваться: вы получите готовую ссылку и передадите её сами.

❗️ Сначала привяжите свой Telegram к профилю подписки — без привязки я не узнаю, какая подписка ваша, и напоминания приходить не будут.

Как привязать аккаунт — по шагам:
1. Откройте приложение, в котором вы пользуетесь подпиской, и скопируйте ссылку на подписку.
2. Отправьте эту ссылку мне обычным сообщением в этот чат — команда /register не нужна.
3. Я найду ваш профиль и спрошу «Привязать ваш Telegram к профилю …?» — нажмите кнопку «Привязать».
4. Когда придёт сообщение «✅ Готово!», привязка завершена и напоминания включены.

Нет ссылки под рукой? Нажмите «🔗 Привязать аккаунт» ниже (или отправьте /register) и введите имя профиля (например, ivan_petrov).
Если ошиблись или передумали — отправьте /cancel и начните заново.

Все команды:
/me — личный кабинет: статус подписки, ссылка, подарки
/menu — открыть меню с кнопками
/register — привязать свой Telegram к профилю
/tariff — посмотреть текущие тарифы
/gift — подарить подписку (получателю с Telegram)
/mygifts — мои подарочные подписки и их статус
/invite — оформить подписку человеку без Telegram
/cancel — отменить текущее действие
/help — помощь

[🔗 Привязать аккаунт]
```

## Мини-приложение Telegram

Если задан `WEBAPP_URL`, бот поднимает мини-приложение «Личный кабинет» и
регистрирует его как **кнопку меню** чата (плюс кнопка
«🖥 Открыть мини-приложение» внутри `/me`). В приложении видны привязанные
профили со статусом и сроком действия, ссылка на подписку с копированием в один
тап, реквизиты для оплаты, сводка по подаркам и приглашениям, а также выбор
тарифа с отправкой заявки на продление администратору.

В правом верхнем углу мини-приложения есть **переключатель языка**
(🇷🇺 русский / 🇬🇧 английский). По умолчанию берётся язык Telegram пользователя
(с откатом к `BOT_LANG`), а явный выбор запоминается в браузере. Переключатель
влияет только на интерфейс мини-приложения; данные с сервера (статус подписки,
цены) следуют `BOT_LANG`.

Что нужно:

- Мини-приложение раздаёт сам бот на адресе `WEBAPP_LISTEN` (по умолчанию
  `:8080`). Telegram открывает мини-приложения только по **HTTPS**, поэтому
  поставьте впереди реверс-прокси (nginx / Caddy / Traefik) и укажите в
  `WEBAPP_URL` публичный HTTPS-адрес, который проксирует на порт 8080
  контейнера.
- Запросы аутентифицируются проверкой Telegram `initData` (HMAC-подпись
  токеном бота) — дополнительные пароли и логины не нужны.

Пример с приложенным compose-файлом: раскомментируйте секцию `ports`,
настройте прокси `https://bot.example.com` → `127.0.0.1:8080` и задайте
`WEBAPP_URL=https://bot.example.com`.

### Шаблоны для реверс-прокси

В обоих шаблонах замените `bot.example.com` на свой домен.

**Caddy** (`/etc/caddy/Caddyfile`) — TLS-сертификаты выпускаются и
продлеваются автоматически:

```caddyfile
bot.example.com {
    reverse_proxy 127.0.0.1:8080
}
```

**nginx** (`/etc/nginx/sites-available/remnawake-webapp`) — предполагаются
сертификаты от certbot (`certbot --nginx -d bot.example.com` может добавить
TLS-настройки за вас):

```nginx
server {
    listen 443 ssl;
    http2 on;
    server_name bot.example.com;

    ssl_certificate     /etc/letsencrypt/live/bot.example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/bot.example.com/privkey.pem;

    location / {
        proxy_pass http://127.0.0.1:8080;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}

server {
    listen 80;
    server_name bot.example.com;
    return 301 https://$host$request_uri;
}
```

Включить и перезагрузить:

```bash
sudo ln -s /etc/nginx/sites-available/remnawake-webapp /etc/nginx/sites-enabled/
sudo nginx -t && sudo systemctl reload nginx
```

### Запуск рядом с remnawave (Caddy в контейнере)

Если у вас уже работает [remnawave](https://remna.st) со своим Caddy **в
контейнере**, не используйте пример с `127.0.0.1:8080` выше. Внутри контейнера
Caddy адрес `127.0.0.1` указывает на сам Caddy, а не на хост — поэтому, как и
панель remnawave и страница подписки, бот должен быть доступен по **имени
контейнера** через общую docker-сеть.

**1. Подключите бота к сети remnawave.** В `docker-compose.yml` бота добавьте
внешнюю сеть (и не указывайте блок `ports:` — Caddy достучится до бота по
docker-сети, порт 8080 не нужно публиковать на хост):

```yaml
services:
  bot:
    image: ghcr.io/nakedjustice/remnawake:main
    pull_policy: always
    container_name: remnaWake-bot
    restart: unless-stopped
    env_file:
      - ./.env
    environment:
      DB_PATH: /data/bot.db
    volumes:
      - botdata:/data
    networks:
      - remnawave-network

networks:
  remnawave-network:
    name: remnawave-network
    external: true

volumes:
  botdata:
```

**2. Добавьте сайт в существующий `Caddyfile`** рядом с записями remnawave,
проксируя на имя контейнера и порт бота:

```caddyfile
https://bot.example.com {
    reverse_proxy remnaWake-bot:8080
}
```

**3. Укажите этот адрес в `WEBAPP_URL`** в `.env`:

```
WEBAPP_URL=https://bot.example.com
```

Затем поднимите бота и перезагрузите Caddy:

```bash
docker compose up -d            # в каталоге remnaWake
docker compose restart caddy    # в каталоге caddy
```

Убедитесь, что `bot.example.com` указывает на этот сервер в DNS до перезагрузки,
иначе Caddy не сможет выпустить сертификат.

## Запуск

### Установка на сервер (рекомендуется)

Одна команда скачивает проект в **`/opt/remnaWake`** и запускает интерактивный
установщик. Для установки в `/opt` нужны права root, поэтому запускайте от root
или через `sudo`:

```bash
curl -fsSL https://raw.githubusercontent.com/Nakedjustice/remnaWake/main/get.sh | sudo bash
```

Чтобы установить в другое место (для доступного на запись пути root не нужен),
задайте `TARGET_DIR`:

```bash
curl -fsSL https://raw.githubusercontent.com/Nakedjustice/remnaWake/main/get.sh | TARGET_DIR="$HOME/remnaWake" bash
```

Предпочитаете вручную?

```bash
sudo git clone https://github.com/Nakedjustice/remnaWake.git /opt/remnaWake
cd /opt/remnaWake
sudo ./install.sh
```

Установщик спросит URL панели, API-токен, токен бота, Telegram ID администратора,
таймзону и время запуска, запишет `.env` (с правами `600`) и предложит скачать
готовый образ и запустить контейнер через Docker Compose. Нужны `git` (либо
`curl`/`wget`) и Docker Engine с плагином Compose.

### Локально (разработка)

```bash
cp .env.example .env
# отредактируйте .env
go mod download
go run .
```

### Docker (готовый образ)

Готовый к запуску образ публикуется в GHCR, локальная сборка не нужна:

```bash
cp .env.example .env
# отредактируйте .env и укажите TELEGRAM_ADMIN_ID для всех дополнительных сценариев
docker compose up -d          # скачивает ghcr.io/nakedjustice/remnawake:latest
docker compose logs -f
```

Чтобы обновиться позже, скачайте свежий образ и пересоздайте контейнер:

```bash
docker compose pull && docker compose up -d
```

### Docker (сборка из исходников)

Если вы изменили код (или используете свой форк) и хотите собрать образ локально
вместо скачивания, используйте override-файл для сборки:

```bash
docker compose -f docker-compose.yml -f docker-compose.build.yml up -d --build
```

## Поведение

- Если ответ Remnawave содержит `total > size`, сервис догружает остальные страницы.
- На `401` от `/api/users` проверьте `REMNAWAVE_API_TOKEN`. Ошибка логируется, job не падает.
- Telegram `429` логируется с указанием `retry_after`, остальные пользователи
  продолжают обрабатываться.
- При заданном `TELEGRAM_ADMIN_ID` бот запускает long polling для
  `callback_query` и `message`, чтобы обрабатывать все inline-кнопки и команды.
- Дедупликация уведомлений — точное совпадение оставшихся дней (`7/3/1`) на дату
  запуска. Состояние уведомлений не сохраняется.

## Развёртывание своей копии

Чтобы разместить бота в своём репозитории GitHub (чтобы установщик в одну строку
работал для вас и ваших пользователей), запушьте проект в **публичный** репозиторий:

```bash
# из каталога проекта
git remote add origin https://github.com/<вы>/<репозиторий>.git
git push -u origin main
```

Затем замените `Nakedjustice/remnaWake` (и ветку `main`) на свой
`<вы>/<репозиторий>` в файлах `get.sh`, `README.md` и `README.ru.md`, а также путь
`module` в `go.mod`. Файл `.env` добавлен в `.gitignore` и никогда не пушится —
ваши API-токены остаются приватными.

Workflow `.github/workflows/docker-publish.yml` публикует готовый образ в **ваш**
GHCR (`ghcr.io/<вы>/<репозиторий>`, в нижнем регистре) при каждом пуше в `main`.
Обновите строку `image:` в `docker-compose.yml` под свой `ghcr.io/<вы>/<репозиторий>`
(в нижнем регистре). Пакет создаётся после первого успешного запуска — сделайте
его публичным в настройках **Packages** репозитория, чтобы пользователи могли
скачивать образ без авторизации. До этого (и в любой момент) можно собирать из
исходников через override `docker-compose.build.yml`, показанный выше.

После пуша проверьте, что установщик доступен:

```bash
curl -fsSL https://raw.githubusercontent.com/<вы>/<репозиторий>/main/get.sh | head -5
```
