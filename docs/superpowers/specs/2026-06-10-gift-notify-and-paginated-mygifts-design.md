# Уведомление о заявке на гифт + постраничный список «Мои подарки»

Дата: 2026-06-10. Статус: утверждено пользователем.

## 1. Уведомление об отправке заявки администратору

Сейчас после выбора тарифа в гифт-флоу пользователь получает только toast
(`AnswerCallbackQuery`), а у сообщения с тарифами просто снимаются кнопки.

Изменение: в `handleGiftCodePick` после успешного создания заявки текст
сообщения с выбором тарифа редактируется на:

> ✅ Заявка на подарочную подписку (N мес.) отправлена администратору.
> Ожидайте подтверждения оплаты.

Кнопки убираются (EditMessageText без клавиатуры). Toast остаётся.
Если в телеграм-клиенте нет `EditMessageText` — добавить по образцу
`EditMessageReplyMarkup`.

## 2. «Мои подарки»: меню статусов + пагинация

Поток: кнопка «📦 Мои подарки» / `/mygifts` → сообщение-меню
«Выберите статус подарков» с 5 кнопками (с количеством):

- ⏳ Ожидают оплаты (pending)
- 📨 Выданные (issued)
- ✅ Активированные (redeemed)
- ❌ Отклонённые (rejected)
- 🚫 Отозванные (revoked)

Нажатие на статус редактирует то же сообщение: до 5 подарков статуса
(код, срок, дата заявки), внизу:

- для issued — кнопки «🔗 Ссылка для CODE» по подаркам текущей страницы
  (существующий callback `gc_link:<id>`);
- «◀️» / «стр. X/Y» / «▶️» — только если страниц больше одной
  (кнопка-индикатор страниц — no-op);
- «← К статусам» — возврат в меню.

Callback-данные: `mg:menu`, `mg:list:<status>:<page>` (страница с 0).
Состояние в памяти не хранится — всё в callback data, переживает рестарт.
Если на запрошенной странице пусто (список изменился) — показать первую
страницу; если подарков статуса нет вообще — текст «пусто» и кнопка
«← К статусам».

## Хранилище

Новые методы в `internal/store/gifts.go`:

- `ListGiftCodesByBuyerStatus(ctx, buyerTGID, status, limit, offset) ([]GiftCode, error)`
- `CountGiftCodesByBuyerStatus(ctx, buyerTGID, status) (int, error)`
- `CountGiftCodesByBuyer(ctx, buyerTGID) (map[string]int, error)` — для
  количества в кнопках меню.

`ListGiftCodesByBuyer` остаётся (используется тестами/другими местами) либо
удаляется, если больше не нужен.

## Тесты

- store: фильтр по статусу, limit/offset, счётчики.
- payments: меню статусов, страница списка, перелистывание, пустой статус,
  кнопки ссылок на странице issued, текст уведомления после gc_pick.
